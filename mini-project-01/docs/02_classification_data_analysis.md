## 1. 데이터 탐색 및 클래스 분포 (CP-01)

- **데이터 크기:** 12330행, 18열
- **결측값 및 중복 행:** 결측값 0, 중복 125행 (중복 행을 삭제하지 않은 이유: 다른 유저가 같은 행동 패턴을 보였을수 있으므로 삭제하지 않고 유지합니다.)
- **수치형 특성 분포의 특징(`ProductRelated`, `PageValues` 등):** 여러 페이지를 보거나, 페이지에서 오래 머물거나 다양한 페이지를 보는 경우보다 특정페이지를 적게 보고 페이지에 짧게 머물면서 구매하는 사람이 많습니다. 그리고 ExitRates는 다른 특성들과 달리 0.01부근과 0.2에서 수치가 튀는형태입니다. 이탈율이 낮은곳에 세션이 몰려있다는것은 여러페이지를 둘러보았다는것이고, 높은곳에 몰린것은 페이지를 적게 보고 이탈한 세션을 의미합니다. 조금 보고 이탈하거나 아니면 여러페이지를 둘러보는 사용자로 크게 분류할수 있습니다.
- **구매(`Revenue=1`) 건수와 비율:** 1908건 / 15.47%
- **미구매(`Revenue=0`) 건수와 비율:** 10422건 / 84.53%

**분석:** 모두 미구매로 예측했을 때 Accuracy가 약 84.53%인 이유와 이 수치만으로 평가하기 어려운 점을 작성합니다.  
전체 데이터에서 미구매가 차지하는 비율이 높아서 미구매가 예측이 될 확률이 높습니다. 그래서 지금  미구매에 높은 확률이 나왔다고 해서 나중에 구매/미구매 비율이 달라졌을때도 똑같이 높은 확률이 나오리라는 보장이 없습니다.

## 2. 계층화 데이터 분할 (CP-02)

- **Train:** 8630건 / 구매 비율 15.48%
- **Validation:** 1850건 / 구매 비율 15.46%
- **Test:** 1850건 / 구매 비율 5.46%
- **`stratify`를 적용한 이유:** 지정한 비율의 양으로 데이터를 분할하기위해
- **1일차 회귀의 날짜 순서 분할과 다른 이유:** 날짜는 순서를 유지해야 시간에 흐름에 따라서 달라지는 데이터를 분석,예측할수 있고, 지금은 순서와 상관없이 구매/비구매 여부를 예측하기 때문입니다.

**분석:** Train·Validation·Test의 구매 비율이 유사한지 확인하고 의미를 1~2문장으로 작성합니다.  
데이터셋의 구매 비율이 15.46%로 동일하게 분할 되었습니다. 이유는 데이터셋의 구매여부 비율이 원본 데이터와 동일해야 모델성능을 실제 데이터에 맞게 평가할 수 있기 때문입니다.

## 3. 구매 여부와 관련된 특성 분석 (CP-02)

- **방문자 유형(`VisitorType`)별 구매율:** Returning_Visitor 13.95% / New_Visitor 25.22% / Other 15.87%
- **구매율이 가장 높은 방문자 유형:** New_Visitor
- **구매·미구매 세션의 `ProductRelated` 중앙값:** 29.0 / 16.0
- **구매·미구매 세션의 `ProductRelated_Duration` 중앙값:** 1069.658 / 517.580	
- **구매·미구매 세션의 `PageValues` 중앙값:** 17.543 / 0.000
- **구매·미구매 세션의 `ExitRates` 중앙값:** 0.015 / 0.029
- **특성 분석을 Train 데이터에서 수행한 이유:**  Valid, Test 데이터에서 수행하면 답안을 미리 보고 특성을 고르는것이 되어서 데이터 누수가 발생하게 됩니다.

**분석:** 구매 여부와 관련된 특성에서 관찰한 점과 `PageValues`의 예측 시점상 한계를 작성합니다.  
실제 운영중인 사이트에서 나온 데이터를 가지고 학습한 모델로 예측을 하면, 모델에서는 구매페이지로 갔을거라고 예측했는데 운영중인 사이트 데이터에서는 아직 구매페이지까지 가지못한(구매로 이어질 예정인 세션) 데이터때문에 예측이 틀리게 나올수 있습니다. 
만약 PageValues가 세션이 본 페이지들의 가치의 평균 값이 아닌, 세션이 본 각 페이지들의 가치를 저장한 특성이 있었다면 그 페이지가 구매로 이어질 페이지인지 알수 있어서 현재 예측시점의 한계를 극복하여 예측이 가능할 것 입니다.

## 4. 데이터 전처리 및 PyTorch 입력 준비 (CP-03)

- **범주형 특성(One-Hot 인코딩):** [
    # 범주형 컬럼 이름
    "Month",    # 방문 월
    "OperatingSystems",  # 운영 체제
    "Browser",           # 브라우저
    "Region",            # 지역
    "TrafficType",       # 트래픽 유형
    "VisitorType"        # 방문자 유형
]
- **수치형 특성(표준화):** [
    # 수치형 컬럼 이름
    "Administrative",    # 관리 페이지 방문 횟수
    "Administrative_Duration",  # 관리 페이지 체류 시간
    "Informational",     # 정보 페이지 방문 횟수
    "Informational_Duration",   # 정보 페이지 체류 시간
    "ProductRelated",    # 제품 관련 페이지 방문 횟수
    "ProductRelated_Duration",  # 제품 관련 페이지 체류 시간
    "BounceRates",       # 이탈률
    "ExitRates",         # 종료률
    "PageValues",        # 페이지 가치
    "SpecialDay"         # 특별 날짜 여부
]
- **이진 특성(변환 없이 사용):** [
    # 이진형 컬럼 이름
    "Weekend"            # 주말 여부
]
- **숫자로 표현된 코드값(`OperatingSystems`, `Browser` 등)을 범주형으로 처리한 이유:** 운영체제, 브라우저 등을 종류를 구분하는 코드이기때문입니다.
- **`handle_unknown="ignore"`를 설정한 이유:** OneHotEncoder가 학습에 보지 못한 범주를 만났을때 예측 에러가 발생하여 중단됩니다. 0으로 채우면 정보가 없는걸로 처리되어서 예측에 오류가 발생하지 않기때문입니다.
- **Train 전처리 전후 Shape:** (8630, 17) → (8630, 73)
- **Validation에 적용한 변환 기준:** Train 데이터 적용한 변환기준을 똑같이 사용
- **PyTorch 입력·타깃 Tensor의 자료형 및 Shape:** float32, 8630행, 73열
- **`DataLoader` 배치 크기와 배치 수:** 256, 34개

**분석:** 신경망 입력을 `float32` Tensor로 준비하고 미니배치를 만드는 이유를 1~2문장으로 작성합니다.  
PyTorch에서 Tensor 형태로 입력을 받습니다. 또, 계산을 하려면 입력 데이터의 자료형과 가중치의 자료형이 같아야 하는데 가중치가 float32형이 기본값이므로 입력 데이터를 float32형으로 변경했습니다.

손실계산과 기울기 계산을 한 에포크에 한 번 만 갱신하는것보다 자주 갱신하기위해서입니다. 학습이 더 빠르게 진행됩니다.
